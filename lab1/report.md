### 1. Цель работы

**Основные требования к приложению:**
* Наличие полей ввода для точного задания цветов.
* Выбор цвета из палитры (аналогично графическим редакторам)
* Плавное изменение цвета с помощью ползунков.
* Автоматический пересчет значений во всех моделях при изменении любой координаты без потери точности и сбоя интерфейса.

### 2. Теоретическая часть и математический аппарат

Для выполнения расчетов приняты следующие стандартные диапазоны величин:

* **RGB**: $R, G, B \in [0, 255]$ (целые числа), нормализованные значения $r, g, b \in [0, 1]$.
* **CMYK**: $C, M, Y, K \in [0, 1]$ (в интерфейсе отображаются в процентах $[0, 100]\%$).
* **HLS**: Тон $H \in [0, 360]^\circ$, яркость $L \in [0, 1]$, насыщенность $S \in [0, 1]$ (в процентах $[0, 100]\%$).

---

#### 2.1. Преобразования между RGB и CMYK

**Прямое преобразование (из RGB в CMYK):**

1. Нормализация каналов RGB:

$$r = \frac{R}{255}, \quad g = \frac{G}{255}, \quad b = \frac{B}{255}$$


2. Вычисление черного ключа ($K$):

$$K = 1 - \max(r, g, b)$$


3. Если $K = 1$ (абсолютно черный цвет), то компоненты принимают значения: $C = 0, M = 0, Y = 0, K = 1$.
4. Для остальных цветов:

$$C = \frac{1 - r - K}{1 - K}, \quad M = \frac{1 - g - K}{1 - K}, \quad Y = \frac{1 - b - K}{1 - K}$$



**Обратное преобразование (из CMYK в RGB):**


$$R = 255 \times (1 - C) \times (1 - K)$$

$$G = 255 \times (1 - M) \times (1 - K)$$

$$B = 255 \times (1 - Y) \times (1 - K)$$

---

#### 2.2. Преобразования между RGB и HLS

**Прямое преобразование (из RGB в HLS):**

1. Нормализация $R, G, B \in [0, 1]$.
2. Определение максимального, минимального значений и их разницы ($\text{delta}$):

$$\max = \max(r, g, b), \quad \min = \min(r, g, b), \quad \text{delta} = \max - \min$$


3. Расчет яркости ($L$):

$$L = \frac{\max + \min}{2}$$


4. Расчет насыщенности ($S$):
* Если $\max == \min$ (ахроматический цвет): $S = 0$
* Если $L \le 0.5$:

$$S = \frac{\text{delta}}{\max + \min}$$


* Если $L > 0.5$:

$$S = \frac{\text{delta}}{2.0 - \max - \min}$$




5. Расчет тона ($H$):
* Если $\max == \min$, тон условно принимается равным текущему значению.
* Иначе в зависимости от максимального канала:
* Если $\max == r$:

$$H = \left(\frac{g - b}{\text{delta}}\right) \pmod 6$$


* Если $\max == g$:

$$H = \frac{b - r}{\text{delta}} + 2.0$$


* Если $\max == b$:

$$H = \frac{r - g}{\text{delta}} + 4.0$$




* Перевод в градусы: $H = H \times 60^\circ$. Если $H < 0$, добавляется $360^\circ$.



**Обратное преобразование (из HLS в RGB):**
Если насыщенность $S = 0$, то цвет ахроматический: $R = G = B = L \times 255$.
При $S > 0$:

1. Промежуточная хрома ($c$) и параметры расчета:

$$c = (1 - \vert{}2L - 1\vert{}) \times S$$


$$x = c \times (1 - \vert{}\left(\frac{H}{60}\right) \pmod 2 - 1\vert{})$$


$$m = L - \frac{c}{2}$$


2. В зависимости от сектора угла $H$:
* $0^\circ \le H < 60^\circ: (r', g', b') = (c, x, 0)$
* $60^\circ \le H < 120^\circ: (r', g', b') = (x, c, 0)$
* $120^\circ \le H < 180^\circ: (r', g', b') = (0, c, x)$
* $180^\circ \le H < 240^\circ: (r', g', b') = (0, x, c)$
* $240^\circ \le H < 300^\circ: (r', g', b') = (x, 0, c)$
* $300^\circ \le H < 360^\circ: (r', g', b') = (c, 0, x)$


3. Масштабирование до диапазона $[0, 255]$:

$$R = \text{round}((r' + m) \times 255)$$


$$G = \text{round}((g' + m) \times 255)$$


$$B = \text{round}((b' + m) \times 255)$$

### 3. Особенности реализации и решение граничных случаев

При разработке интерактивного веб-приложения были учтены и программно решены следующие сложные технические задачи:

1. **Проблема «прыгающих ползунков» (цикличность событий):**
* Для предотвращения конфликтов при двустороннем пересчете введен глобальный флаг блокировки `activeModel`. Он фиксирует модель, с которой в данный момент взаимодействует пользователь, запрещая её перезапись обратными математическими функциями.


2. **Деление на ноль для модели CMYK:**
* При $K = 1$ (абсолютно черный цвет) знаменатель формул $(1 - K)$ обращается в ноль. В коде реализована проверка: если $K \ge 1$, приложение берет текущие значения компонентов из полей ввода, избегая ошибок `NaN` и резких скачков ползунка Cyan.


3. **Неопределенность тона ($H$) для ахроматических цветов:**
* При $\Delta = 0$ (черный, белый, серый цвета) тон $H$ математически не определен. Вместо принудительного сброса в $0^\circ$ (что вызывало скачки ползунка Hue) в алгоритме сохраняется текущее пользовательское значение тона.
